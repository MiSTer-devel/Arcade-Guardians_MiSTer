## MiSTer framework

The `sys` integration is derived from the MiSTer FPGA framework and retains the
copyright and license headers in every source file. Named contributors in the
bundled framework sources include Alexey Melnikov, Till Harbaum, Sorgelig,
Ludvig Strigeus, Kitrinx, Mike Simone, Grabulosaure, and bellwood420. MiSTer is
developed by the wider MiSTer-devel community.

## CRT geometry

The optional CRT geometry output stages are adapted from
[`MiSTer-CRT-Adjust`](https://github.com/rmonic79/MiSTer-CRT-Adjust) by
Umberto Parisi (rmonic79), with contributions to `crt_adjust.sv` credited in
its source header to Andrea Bogazzi (@asturur). The adapted source retains its
GNU GPL v3-or-later notice. Guardians stores its native RGB555 pixels directly
in these line buffers, preserving every palette bit while reducing FPGA block
RAM use.

## Hardware documentation and behavioral references

Public MAME source was used as hardware documentation and a behavioral
reference. No MAME source code is copied into the core. In particular:

- [`seta2.cpp`](https://github.com/mamedev/mame/blob/master/src/mame/seta/seta2.cpp):
  Luca Elia and David Haywood
- [`x1_020_dx_101.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/video/x1_020_dx_101.cpp):
  Luca Elia and David Haywood
- [`x1_010.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/sound/x1_010.cpp):
  Luca Elia; its source comments also credit Manbow-J for a rewrite
- [`tmp68301.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/cpu/m68000/tmp68301.cpp):
  Olivier Galibert

The emulated devices include the Toshiba TMP68301, NEC DX-101 / Allumer X1-020,
and Seta X1-010. Device and company names are used only to identify the original
hardware.

## Cheat definitions

The optional cheats use address/value definitions from
[Pugsy's MAME Cheat Collection](https://www.mamecheat.co.uk/). Its Guardians
entry credits the game-specific definitions used here to pasky13. The public
XML was used as a behavioral reference and is not bundled.

The standard MRA-code storage and matching model in
[`rtl/gd_mra_cheat_engine.sv`](rtl/gd_mra_cheat_engine.sv) is adapted from
Martin Donlon's GPL-2.0-or-later `cheatengine_32_16` in the
[MiSTer Irem M92 core](https://github.com/MiSTer-devel/Arcade-IremM92_MiSTer),
which credits Kitrinx for the original cheat-code handling. Guardians adds the
big-endian byte and long-word lane mapping required by its TMP68301/68000 bus.

## Generated FPGA IP

PLL files generated by Intel/Altera Quartus Prime are included because they are
required to reproduce the build. They retain their generated notices and are
subject to the applicable Intel/Altera FPGA IP terms. Those files are intended
for programming supported Intel/Altera programmable-logic devices.
